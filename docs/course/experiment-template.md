# Optional experiment record

Use this structure inside your existing course record or issue; it is not an additional required submission.

- **Question and reason:** What specific failure or uncertainty are you investigating?
- **Baseline:** Commit/image digest, OS/hardware, role/model/revision, relevant configuration, permitted input and question.
- **Prediction:** What do you expect to change, and why?
- **One bounded change:** Identify the module/configuration and explain its responsibility.
- **Evidence:** Expected versus actual retrieved IDs, extracted inputs, answer, citations, terminal state and latency. Include unsuccessful results.
- **Human review:** Which claims are supported? Which are missing, misattributed or invented?
- **Comparison:** What improved, what regressed and what remains untested?
- **Next decision:** Keep, revise or revert the change; state the evidence for that decision.

Use synthetic/permitted examples. Keep keys, private conversations and personal media out of public records. Link to exact source revisions and reproducible commands where possible.
